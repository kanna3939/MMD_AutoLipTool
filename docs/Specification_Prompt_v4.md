## 1. 目的

`MMD_AutoLipTool` は、Windows 向けの MikuMikuDance（MMD）用リップモーション生成ツールである。

本ツールの目的は、UTF-8 テキストと音声ファイルを入力し、MMD の母音モーフ `あ / い / う / え / お` を用いた VMD リップモーションを生成することである。

現行 Ver0.4 系では、wxPython 主系の GUI 上で以下を提供する。

- TEXT 読込
- WAV 読込
- 音声タイミング解析
- 母音イベント生成
- VMD リップモーション出力
- 波形表示
- Preview 表示
- 再生位置表示
- Viewport / Zoom / 自動追従
- 最近使ったファイル履歴
- 設定保存・復元
- 処理中の安全制御

MS16以降では、以下の拡張を予定または検討対象とする。

- mp3入力対応
- FFmpeg / ffprobe を用いた音声変換
- MMD用WAV同時出力
- 配布ZIP整備
- onefile配布前提の安全性強化

## 5. アーキテクチャ方針

### 5.1 基本方針

本ツールは、以下の責務分離を基本とする。

- `core`
  - テキスト処理
  - 音声解析
  - タイミング計画
  - RMS / peak 評価
- `vmd_writer`
  - VMD出力
  - モーフキーフレーム生成
  - 最終正規化
- `gui_wx`
  - 入出力導線
  - GUI状態管理
  - 表示
  - Preview
  - 再生制御
  - ユーザー操作
- docs
  - 仕様
  - 実装計画
  - マイルストーン履歴
  - 配布文書
  - ライセンス補助文書

### 5.2 エントリーポイント

正式入口は以下とする。

```text
src/main.py
```

`src/main.py` は、wxPython 主系アプリを起動する。

### 5.3 core の責務

`src/core/` は GUI に依存しない処理を担当する。

対象:

- TEXT読込後の正規化
- かな化
- 母音列抽出
- WAV基本情報取得
- 波形プレビュー用データ取得
- Whisperによるタイミング取得
- RMS系列生成
- timing plan 構築
- observation 生成
- writer へのデータ引き渡し

core は wxPython に依存しない。

### 5.4 vmd_writer の責務

`src/vmd_writer/` は VMD出力を担当する。

対象:

- 母音モーフ `あ / い / う / え / お` のキーフレーム生成
- event / timeline からのモーフ形状生成
- peak_value の反映
- closing hold / closing softness の反映
- bridge / smoothing 系の出力反映
- 重複フレームの正規化
- 不要ゼロの整理
- VMDファイル書き出し

writer は GUI 状態に依存しない。

### 5.5 gui_wx の責務

`src/gui_wx/` は wxPython GUI の主系である。

対象:

- アプリ起動
- MainFrame 構築
- メニュー構築
- TEXT / WAV 読込導線
- 処理実行導線
- VMD保存導線
- 再生導線
- 波形表示
- Preview表示
- Viewport制御
- Zoom制御
- Theme制御
- Busy制御
- エラー表示
- 状態管理
- 設定保存・復元

### 5.6 状態管理方針

GUI状態は `UiState` を中心に扱う。

状態分類の例:

- 入力未読込
- TEXT読込済み
- WAV読込済み
- 解析可能
- 解析中
- 解析完了
- 再生可能
- 再生中
- 保存可能
- エラー状態
- 再解析待ち

ただし、状態は単一の線形FSMとして過剰に固定せず、必要に応じて以下を分離して扱う。

- `is_busy`
- `analysis_ready`
- `playback_ready`
- `is_playing`
- `has_text`
- `has_wav`
- `has_valid_timing_plan`

### 5.7 Controller 方針

`app_controller.py` は、MainFrame からの要求を受け取り、処理の委譲・設定保存・テーマ変更などを担当する。

MainFrame にすべての処理を集中させない。

ただし、GUIの有効/無効や表示更新の最終反映は MainFrame 側に残してよい。

### 5.8 Worker 方針

長時間処理は GUIスレッドを塞がない。

対象例:

- Whisper解析
- RMS評価
- timing plan 生成
- 将来のmp3変換
- FFmpeg / ffprobe 実行

worker 処理では、以下を守る。

- 処理中表示を行う
- 二重実行を防ぐ
- キャンセルまたは中止導線を検討する
- 遅れて返った古い結果を破棄する
- UI破棄後にコールバックで触らない
- 例外発生時に例外種別とエラーメッセージを失わない

## 6. 入力仕様

### 6.1 TEXT入力

TEXT入力の基本仕様は以下とする。

- ファイル入力
- UTF-8 を基本とする
- Shift_JIS / UTF-16 のフォールバックを許可してよい
- 通常の日本語台詞文・字幕文・音声合成原稿・文字起こし文を想定する
- 入力内容をコードや命令として評価しない

### 6.2 TEXT入力上限

TEXT入力には以下の上限を適用する。

| 項目 | 条件 | 扱い |
| --- | --- | --- |
| 総文字数 | 5,000文字超 | エラー |
| 1行長 | 500文字超 | 警告対象 |
| 1行長 | 2,000文字超 | エラー |
| 制御文字 | 改行・タブ以外 1〜4文字 | 除去して警告可 |
| 制御文字 | 改行・タブ以外 5文字以上 | エラー |
| 同一記号連続 | 100文字超 | 警告対象 |
| 記号のみ長大行 | 300文字超 | エラー |

### 6.3 WAV入力

現行の基本音声入力は PCM WAV とする。

対応対象:

- PCM
- 16bit
- 44.1kHz または 48kHz

検証対象:

- RIFF / WAVE ヘッダ
- PCM形式
- bit深度
- sampling rate
- チャンネル数
- データ長整合
- 音声長

### 6.4 WAV長さ上限

| 項目 | 上限 |
| --- | --- |
| WAV長さ | 15分 |

15分を超える場合は原則としてエラー停止とする。

### 6.5 mp3入力

mp3入力は MS16以降の設計対象とする。

本書作成時点では、mp3入力は実装済みとして扱わない。

mp3対応時の基本方針:

- mp3を直接解析対象にしない
- FFmpeg等でWAVへ変換する
- 変換後WAVに対して通常WAVと同じ安全検証を行う
- 変換失敗時はVMD生成へ進まない
- 不完全な変換ファイルを残さない

### 6.6 counterpart auto-load

TEXTまたはWAVの読込時、同一フォルダ・同一stemの相方ファイルを自動探索してよい。

方針:

- `.txt` 読込時は `.wav` を探す
- `.wav` 読込時は `.txt` を探す
- 対象拡張子は `.txt / .wav`
- 拡張子の大小文字は区別しない
- 主読込失敗時は補完しない
- 補完側からさらに連鎖しない
- 相方未存在時はサイレントでよい
- 補完側読込失敗時の警告有無は、実装方針に従う
- Recent Files からの読込でも、安全に扱える範囲で発動してよい

mp3対応後に counterpart auto-load の対象へ `.mp3` を含めるかは、MS16実装計画で判断する。

## 7. 出力仕様

### 7.1 VMD出力

出力するVMDは、MMD用のリップモーションVMDとする。

対象:

- モーフキーフレーム
- 母音モーフ `あ / い / う / え / お`

非対象:

- ボーンキーフレーム
- カメラ
- 照明
- 表情全般
- 物理演算
- MMDモデル改変

### 7.2 フレーム基準

フレーム基準は 30fps とする。

内部処理では秒ベースを保持してよいが、最終VMDではフレーム番号へ変換する。

### 7.3 モーフ値

モーフ値は、event単位の `peak_value` を基本とする。

最終書込時には必要最小限の丸めを行う。

モーフ値は、原則として `0.0` から `1.0` の範囲に収める。

### 7.4 キーフレーム上限

| 項目 | 上限 |
| --- | --- |
| モーフキーフレーム総数 | 22,000 |

上限超過時はエラー停止する。

黙って切り詰めたり、一部を削除して成功扱いしてはならない。

### 7.5 VMD保存先

VMD保存時は、利用者に保存先を選択させる。

方針:

- 最後に正常保存したフォルダを記憶してよい
- 同名ファイルが存在する場合は上書き確認を行う
- 保存失敗時は明示通知する
- 不完全な出力ファイルを可能な限り残さない

### 7.6 MMD用WAV同時出力

MMD用WAV同時出力は、MS16以降の設計対象とする。

想定方針:

- mp3入力時に、解析用WAVとは別にMMD読み込み用WAVを出力する
- VMDと同じフォルダへの出力を基本候補とする
- VMDとWAVの対応が分かるファイル名にする
- 同名ファイルがある場合は上書き確認を行う
- 出力失敗時に不完全WAVを残さない
- VMDのみ成功 / WAVのみ成功 / 両方失敗の扱いを明示する

本書作成時点では実装済みとして扱わない。

### 8.3 主要操作

主要操作は以下とする。

- WAV読み込み
- 処理実行
- VMD保存
- Play
- Stop
- Zoom In
- Zoom Out
- Reset Zoom
- テーマ切替

### 8.4 操作有効条件

基本条件:

| 操作 | 有効条件 |
| --- | --- |
| 処理実行 | TEXTとWAVが有効に読み込まれている |
| VMD保存 | 解析結果が有効である |
| Play | 再生可能なWAVが読み込まれている |
| Stop | 再生中である |
| Zoom | WAVまたは表示対象データが存在する |
| テーマ切替 | 常時可能でよい |

Busy中は、状態破壊につながる操作を抑止する。

### 8.5 Busy表示

処理中はBusy状態を明示する。

対象:

- Whisper解析
- timing plan生成
- 将来のmp3変換
- 将来のMMD用WAV出力

Busy状態では以下を守る。

- 二重実行を防ぐ
- 関連ボタンを無効化する
- 処理中表示を行う
- 完了・失敗・キャンセルのいずれでも状態を復帰させる

### 8.6 解析中止

長時間解析では、分析中止導線を持つことが望ましい。

中止時は以下を守る。

- 中止要求後の古い結果を反映しない
- UIを再実行可能状態へ戻す
- 中止を保存可能な成功状態として扱わない

### 8.7 長時間処理警告

長時間処理では、一定時間後に警告または進行中表示を出してよい。

例:

- Whisper解析が長引いている
- mp3変換が長引いている
- 大きなファイルの処理に時間がかかっている

### 8.8 テーマ

テーマは以下を対象とする。

- Light
- Dark
- System

テーマ設定は保存・復元対象とする。

波形表示、Preview表示、ラベル、背景、境界線はテーマに追従する。

### 8.9 Recent Files

TEXT / WAV の最近使ったファイル履歴を保持してよい。

方針:

- 最大10件
- 重複時は先頭へ移動
- 存在しないパスは起動時または表示時に整理してよい
- 読込失敗時の履歴更新は実装方針に従う
- Recent Files からの読込失敗時は安全に通知する

### 8.10 GUI更新・再描画・テーマ追従の必須ルール

GUI部品を追加・変更・差し替える場合は、表示更新・再描画・テーマ追従を実装範囲に含める。

特に、Codex にGUI実装を依頼する場合、以下は「後回しの見た目調整」ではなく、GUI実装の受け入れ条件として扱う。

- 新規ウィジェット追加後にレイアウトが更新されること
- 表示内容変更後に必要な再描画が行われること
- Light / Dark / System テーマ切替に追従すること
- 既存テーマ切替後に、新規追加部品だけ旧色・既定色のまま残らないこと
- enabled / disabled 状態の見た目がテーマ内で視認可能であること
- エラー表示、警告表示、処理中表示もテーマと矛盾しないこと
- Preview / Waveform / Status / Dialog の表示更新が、状態変更後に取り残されないこと

wxPython実装では、必要に応じて以下を行う。

- 親Sizerまたは親Windowの `Layout()` を呼ぶ
- 表示内容変更後に `Refresh()` を呼ぶ
- 即時反映が必要な場合は `Update()` を検討する
- サイズ変更を伴う場合は `Fit()` / `SetMinSize()` / `SendSizeEvent()` の要否を確認する
- カスタム描画部品では、内部状態更新後に再描画要求を出す
- テーマ変更時は、ウィンドウツリー全体にテーマを再適用する
- テーマ適用後に、必要な部品を再描画する

GUI変更時は、単に部品を生成するだけでなく、以下の状態変化で表示が破綻しないことを確認する。

- 起動直後
- TEXT読込後
- WAV読込後
- 処理実行中
- 処理成功後
- 処理失敗後
- 再生中
- 停止後
- テーマ切替後
- 入力再読込後
- Preview / Waveform クリア後

### 8.11 ダイアログのテーマ追従

新規ダイアログを追加する場合は、テーマ追従を必須条件とする。

対象となるダイアログの例:

- エラーダイアログ
- 警告ダイアログ
- 処理中ダイアログ
- 分析中止確認ダイアログ
- 上書き確認ダイアログ
- 設定ダイアログ
- 将来のmp3変換確認ダイアログ
- 将来のMMD用WAV出力確認ダイアログ
- About / Help 系ダイアログ

新規ダイアログでは、少なくとも以下を確認する。

- 背景色が現在テーマに追従する
- 文字色が現在テーマに追従する
- ボタン、ラベル、テキスト欄の視認性が保たれる
- Darkテーマ時に黒文字が黒背景へ埋もれない
- Lightテーマ時に白文字が白背景へ埋もれない
- disabled状態の表示が判別できる
- ダイアログ生成時点で現在テーマを適用する
- テーマ切替後に再度開いたダイアログにも新テーマが反映される

共通のテーマ管理機構がある場合、新規ダイアログは独自に色をハードコードせず、その機構を利用する。

ただし、OS標準ダイアログなどテーマ制御が困難なものについては、無理に独自描画へ置き換えず、制御できない範囲を明記する。

### 8.12 GUI変更時の受け入れ条件

GUI周りの変更・実装を行った場合、以下を受け入れ条件に含める。

#### 共通

- 追加したGUI部品が表示される
- 既存レイアウトを壊していない
- リサイズ時に表示が破綻しない
- 必要な `Layout()` / `Refresh()` / `Update()` が行われている
- 状態変更後に古い表示が残らない
- 既存の操作有効/無効ルールと矛盾しない
- Light / Dark / System テーマに追従する
- 新規部品だけテーマ未適用になっていない

#### ダイアログ

- 現在テーマで表示される
- ダイアログ内の文字が読める
- ボタンの視認性が保たれる
- エラー・警告・確認内容が過不足なく表示される
- 閉じた後に親画面の状態が破綻しない

#### Preview / Waveform

- 入力変更時にクリアされる
- 解析成功時に更新される
- 解析失敗時に古い成功結果が残らない
- 再生位置カーソルが更新される
- テーマ変更後に再描画される
- Viewport変更後に表示が更新される

#### 実装報告時の必須記載

GUI変更を行った場合、実装報告には以下を含める。

- 追加・変更したGUI部品
- 再描画・レイアウト更新の対応内容
- テーマ追従の対応内容
- Light / Dark / System で確認した範囲
- ダイアログを追加した場合、そのテーマ適用方法
- 手動確認できていない表示状態

## 9. 波形表示仕様

### 9.1 基本方針

波形表示は、WAV読込後に音声内容を視覚確認するための表示である。

### 9.2 表示対象

- 音声波形
- 時間軸
- 再生位置カーソル
- Viewport範囲
- Zoom状態

### 9.3 描画方針

- wxPythonの描画機構を用いる
- 高負荷にならないよう表示用データを使う
- 高倍率Zoom時にも破綻しない描画を行う
- 表示範囲外の描画は抑制してよい
- データ更新後は必要な再描画を行う
- テーマ変更後は再描画する

### 9.4 Viewport

波形表示はPreview表示と共有Viewportを持つ。

Viewportは秒ベースで扱う。

### 9.5 Zoom

Zoomは段階的に扱う。

想定:

- 1x
- 2x
- 4x
- 8x

Zoom時は、中心位置や再生位置との関係が不自然にならないよう制御する。

### 9.6 自動追従

再生中は、再生位置が表示範囲の一定位置を超えた場合に自動追従してよい。

自動追従は、波形表示とPreview表示の両方に反映する。

## 10. Preview表示仕様

### 10.1 基本方針

Preview表示は、生成されるリップモーションの概略を確認するための表示である。

### 10.2 表示対象

- 母音 `あ / い / う / え / お`
- 5段固定表示
- 各母音の発声区間
- モーフ強度
- 再生位置カーソル
- Viewport範囲

### 10.3 表示データ

Preview表示は、解析結果から生成されたPreview用データを表示する。

GUI表示とVMD出力は、可能な限り同じ内部イベント列に基づく。

ただし、Preview表示用の描画データとVMD出力データは、責務として分離する。

### 10.4 shape-aware Preview

Previewは、単純矩形だけでなく、writer側のshape semanticsを反映できる構造とする。

対象例:

- asymmetric trapezoid
- legacy triangle
- legacy symmetric trapezoid
- multi-point envelope
- closing hold
- closing softness
- same-vowel bridge
- cross-vowel transition bridge

### 10.5 クリア条件

以下の場合、Previewはクリアまたは無効表示へ戻す。

- TEXT再読込
- WAV再読込
- 解析失敗
- 解析キャンセル
- パラメータ変更により再解析待ちになった
- current timing plan が無効化された
- 古いworker結果が破棄された

### 10.6 再描画条件

Preview表示は、以下の場合に必要な再描画を行う。

- 解析結果が更新された
- Previewデータがクリアされた
- Viewportが変更された
- Zoomが変更された
- 再生位置が変更された
- テーマが変更された
- 表示サイズが変更された

## 11. 再生仕様

### 11.1 基本方針

再生機能は、WAV音声と波形 / Preview 表示の同期確認を目的とする。

### 11.2 Play

Playは、再生可能な音声が読み込まれている場合に有効とする。

再生開始位置は、現行仕様に従う。

### 11.3 Stop

Stopは、再生中のみ有効とする。

Stop後は再生中状態を解除する。

### 11.4 再生位置

再生位置は、波形表示・Preview表示・ステータス表示へ反映する。

### 11.5 再生中の制限

再生中は、状態破壊につながる操作を抑止してよい。

例:

- 別ファイル読込
- 解析再実行
- 入力変更
- 保存処理

ただし、Stop操作は常に可能とする。

---

## 12. パラメータ仕様

### 12.1 モーフ上限

モーフ上限値は、出力モーフ値の上限に関わる設定である。

変更時は、既存解析結果を無効化または再解析待ちにする。

### 12.2 開口保持

開口保持は、発声終了付近の口形維持に関わる設定である。

単位は frame とする。

### 12.3 閉口スムーズ

閉口スムーズは、発声終了後の閉口補間に関わる設定である。

単位は frame とする。

### 12.4 変更時の扱い

解析結果に影響するパラメータを変更した場合、既存解析結果をそのまま保存可能状態にしない。

方針:

- 自動再解析は行わない
- 再解析待ち状態にする
- Previewをクリアまたは無効表示にする
- VMD保存を無効化する
- 必要な表示更新・再描画を行う

---

## 13. タイミング生成仕様

### 13.1 基本方針

タイミング生成は、TEXT由来の母音列とWAV由来の音声情報を元に行う。

### 13.2 Whisper利用

Whisperは、音声中の発話タイミング推定に用いる。

方針:

- 単語情報が得られる場合は利用する
- 得られない場合はセグメント情報を利用する
- 失敗時は均等配分フォールバックを検討する
- Whisper失敗をアプリクラッシュにしない

### 13.3 RMS利用

RMSは、発声区間補正や peak_value 評価に用いる。

方針:

- RMS系列が得られる場合は利用する
- 得られない場合は保守的fallbackを用いる
- RMSが得られないことを、必要に応じてobservationへ記録する

### 13.4 observation

timing plan には、必要に応じて observation を付与する。

observation は以下の追跡に用いる。

- 元 interval
- 補正後 interval
- peak window
- local peak
- global peak
- fallback理由
- window sample数
- short span
- bridge対象
- smoothing判断材料

observation は、writer入力そのものとは分離して扱う。

---

## 14. VMD writer仕様

### 14.1 基本方針

writerは、timing plan からVMDモーフキーフレームを生成する。

GUI表示やユーザー操作に依存しない。

### 14.2 形状生成

writerは、発声イベントに対して適切なモーフ形状を生成する。

対象:

- short fallback
- legacy triangle
- legacy symmetric trapezoid
- asymmetric trapezoid
- multi-point envelope
- closing hold
- closing softness
- top-end shaping
- bridge / smoothing 系 shape

### 14.3 正規化

最終出力前に、以下を行う。

- `(morph_name, frame_no)` 単位の重複統合
- 非ゼロ優先
- 最大値採用
- 全ゼロ時の1件化
- 不要ゼロの整理
- 正規shapeの保護
- 仕様外非ゼロの除去

### 14.4 開口状態

母音全体の開口状態は、以下で評価してよい。

```text
open_value = max(あ, い, う, え, お)
```

個別モーフの整理は、母音全体の開口・閉口列を破壊しない範囲で行う。

### 14.5 zero-peak

`peak_value == 0.0` 相当のイベントは、出力shape生成やclamp処理で特別扱いする。

zero-only shape を最終出力へ残さない。

### 14.6 bridge / smoothing

speech-internal な短いゼロ区間や母音間遷移は、observationに基づいてbridgeまたはsmoothing対象として扱ってよい。

ただし、過剰な補間により不自然な口形維持を発生させない。

## 15. 設定永続化仕様

### 15.1 基本方針

設定永続化では、壊れた設定で起動不能にしないことを優先する。

### 15.2 保存対象

保存対象候補:

- ウィンドウサイズ
- ウィンドウ位置
- テーマ
- 最近使ったTEXTファイル
- 最近使ったWAVファイル
- 最後に使った保存先
- パラメータ値
- 将来のmp3変換関連設定

### 15.3 破損時

設定ファイル破損時は、安全なデフォルトで起動する。

破損設定を無理に採用しない。

### 15.4 保存失敗時

保存失敗時は明示通知する。

ただし、設定保存失敗を理由にアプリ全体を終了させる必要はない。

### 15.5 onefile時の注意

onefile実行時は、一時展開先を設定保存先として扱わない。

exe配置先が書き込み不可の場合は、保存失敗として扱い、利用者へ通知する。

## 16. エラーハンドリング仕様

### 16.1 基本方針

エラー時は、安全な失敗を優先する。

エラーは無言で握りつぶさず、利用者または開発者が原因を切り分けられる情報を残す。

### 16.2 入力エラー

入力エラーでは以下を行う。

- GUI上で明示通知する
- 処理実行へ進ませない
- 古い解析結果を成功扱いしない
- アプリ全体は継続利用可能にする

### 16.3 解析エラー

解析エラーでは以下を行う。

- Busy状態を解除する
- 処理中表示を閉じる
- 解析結果を無効化する
- 保存を無効化する
- 再実行可能状態へ戻す
- 例外種別またはエラーメッセージを確認できるようにする

### 16.4 出力エラー

出力エラーでは以下を行う。

- 保存失敗を明示する
- 不完全ファイルを可能な限り削除する
- 古い正常ファイルを破壊しない
- 保存完了扱いにしない
- 例外種別またはエラーメッセージを確認できるようにする

### 16.5 外部ツールエラー

FFmpeg / ffprobe を使う場合、外部ツールエラーでは以下を行う。

- 終了コードを確認する
- タイムアウトを扱う
- 変換後ファイルを検証する
- 失敗時はVMD生成へ進まない
- 詳細ログの表示は必要最小限にする
- 失敗理由を確認できるようにする

### 16.6 例外・未定義エラーの扱い

予期しない例外や未定義エラーが発生した場合、アプリが無言で停止したり、何も表示せず処理だけ失敗した状態にしてはならない。

少なくとも、利用者または開発者が原因を切り分けられるように、Pythonの例外クラス名またはエラーメッセージを確認できる状態にする。

基本方針:

- 予期しない例外は握りつぶさない
- `except Exception:` で捕捉する場合も、例外情報を失わない
- 利用者向け要約メッセージを表示する
- 詳細情報として Python の例外クラス名とメッセージを表示またはコピー可能にする
- 可能であれば traceback を詳細表示に含める
- 内部詳細を常時前面に出すのではなく、詳細表示として開ける形式を優先する
- エラー後は可能な限り再実行可能状態へ戻す

表示すべき最低限の情報:

```text
エラー種別: <Python exception class name>
エラーメッセージ: <exception message>
発生箇所: <操作名または処理フェーズ>
```

例:

```text
エラー種別: FileNotFoundError
エラーメッセージ: 指定されたファイルが見つかりません
発生箇所: WAV読み込み
```

または:

```text
エラー種別: RuntimeError
エラーメッセージ: FFmpeg conversion failed with exit code 1
発生箇所: mp3変換
```

### 16.7 エラー表示フォーマット

エラー表示は、利用者向け要約と詳細情報を分ける。

#### 利用者向け要約

通常表示では、利用者が次に何をすればよいか分かる短い説明を表示する。

例:

```text
WAVファイルを読み込めませんでした。
ファイル形式が対応外、またはファイルが破損している可能性があります。
```

#### 詳細情報

詳細表示では、開発・問い合わせに使える情報を表示する。

最低限含める項目:

```text
操作:
処理フェーズ:
例外種別:
エラーメッセージ:
対象ファイル:
発生時刻:
```

可能であれば含める項目:

```text
traceback:
worker job id:
input state:
analysis state:
playback state:
```

ただし、以下は必要以上に表示しない。

- 入力テキスト全文
- 個人情報を含むパス
- 音声ファイル内容
- 長大な外部ツールログ全文

フルパスを表示する場合は、問い合わせ用詳細情報として扱い、通常表示ではファイル名のみを優先する。

### 16.8 worker / callback / timer 例外の扱い

GUIスレッド外、worker、timer、callback 内で発生した例外も、無言で失敗させてはならない。

対象例:

- 解析worker
- Whisper解析
- RMS計算
- mp3変換worker
- FFmpeg / ffprobe 実行
- 再生位置更新timer
- wx.CallAfter 経由のcallback
- Preview更新
- Waveform更新
- テーマ適用処理
- ダイアログ生成処理

方針:

- worker内例外はメインスレッドへエラー結果として返す
- callback内例外は可能な限り捕捉し、GUI上で通知する
- timer内例外で無限にエラーが繰り返されないようにする
- エラー発生時は該当timerやworker状態を安全に停止する
- Busy状態を解除する
- UI操作状態を復帰する
- 古い成功結果を現在結果として扱わない
- 例外種別とエラーメッセージを詳細表示へ渡す

worker結果の型やcallback契約には、成功・失敗を明示できる構造を用いる。

例:

```text
success: bool
result: optional result payload
error_type: optional exception class name
error_message: optional exception message
traceback: optional traceback text
phase: operation phase
job_id: worker job id
```

例外を文字列だけに潰して返す場合でも、最低限 `error_type` と `error_message` は失わない。

### 16.9 エラーハンドリング上の禁止事項

以下は禁止する。

- 例外を捕捉して何も表示しない
- `pass` だけで例外を無視する
- `except Exception:` で捕捉した後、例外種別とメッセージを破棄する
- エラー発生後も成功ステータスを表示する
- 解析失敗後に古い解析結果を保存可能状態にする
- worker失敗後にBusy状態を解除しない
- ダイアログ生成失敗を無視して処理を継続する
- テーマ適用失敗を無視して一部UIだけ視認不能にする
- callback例外でアプリが不安定な状態のまま残る

通常利用者には、別途添付する実行用ZIPを案内する。

### 18.5 FFmpeg

本書作成時点では、FFmpeg同梱を確定事項として扱わない。

同梱する場合は、以下を確認する。

- FFmpeg配布元
- GPL / LGPL の区分
- 同梱するバイナリ
- upstream license texts

- Release ZIP内の配置
