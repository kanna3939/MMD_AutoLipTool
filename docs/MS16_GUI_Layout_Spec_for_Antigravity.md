## 2. 文書目的

本書は、`MMD_AutoLipTool` の MS16 における GUI レイアウト方針を固定するための仕様文書である。

MS16 では、以下を主目的とする。

1. wxPython 版 Preview を、現在のリボン型表示から、旧Qt/PySide版に近い **変形台形 / 三角形 / エンベロープ型のリッププレビュー表示**へ戻す。
2. 波形表示とリッププレビューの時間軸・表示範囲・再生カーソルを同期する。
3. 将来の Info / Warning / 選択イベント / プリセット / モデルプロファイル表示に備え、右ペイン型の情報タブ UI を先に確保する。
4. 将来の母音イベント単位編集、調整レイヤー、Undo / Redo、セッション保存に備え、GUI上の配置と責務境界を固定する。
5. ベータ版リリース後に GUI が大きく変わってユーザーを混乱させないよう、MS16 時点で基本レイアウトを固める。

本書は、MS16 の GUI レイアウト仕様を説明するものであり、個別の実装手順書ではない。  
実装時には、別途 `MS16-Bx_Implementation_Plan.md` を作成し、本書を参照する。

## 4. MS16 GUI の基本方針

MS16 の GUI は、以下の基本配置とする。

```text
上部:
  ファイル読込 / 解析 / 保存 / 再生 / Zoom / プリセット選択

左:
  入力情報
  TEXT / ひらがな / 母音列 / 音声情報の概要

中央:
  上: 波形表示
  下: Preview変形台形表示

右:
  情報系タブペイン
    - Info
    - Warning
    - 選択イベント
    - プリセット
    - モデルプロファイル

下部:
  ステータス / 処理状況 / 再生位置
```

この配置は、MMD および各種 DCC 系ツールにおける一般的な情報配置に合わせる。
細かい情報・選択対象詳細・補助設定は右ペインへ寄せ、必要に応じてタブで切り替える。

## 5. 全体レイアウト仕様

### 5.1 レイアウト概要

MS16 GUI は、以下の5領域で構成する。

| 領域 | 役割 |
| --------- | ------------------------------------------- |
| 上部ツールバー | 主要操作、再生、Zoom、プリセット選択 |
| 左ペイン | 入力情報、テキスト、ひらがな、母音列、音声情報の概要表示 |
| 中央ペイン | 波形表示とリッププレビューのメイン表示 |
| 右ペイン | Info / Warning / 選択イベント / プリセット / モデルプロファイル |
| 下部ステータスバー | 解析状態、処理時間、ファイル情報、再生位置など |

### 5.2 レイアウト上の優先順位

画面上の優先順位は以下とする。

1. 中央ペインの波形表示とリッププレビュー
2. 上部ツールバーの主要操作
3. 右ペインの情報タブ
4. 左ペインの入力概要
5. 下部ステータスバー

最も重要なのは、中央ペインである。
波形とリッププレビューは、ユーザーが生成結果を確認する主要領域であるため、可能な限り広く確保する。

### 5.3 ウィンドウサイズ

MS16 では、将来の右情報ペインを含めるため、現在の wx 版よりウィンドウサイズを大きめにしてよい。

ただし、以下を満たすこと。

* Windows 11 の一般的なフルHD環境で利用できること
* 画面から大きくはみ出さないこと
* 初期表示で主要操作が見えること
* 波形表示とPreview表示が極端に狭くならないこと

## 6. 上部ツールバー仕様

### 6.1 目的

上部ツールバーは、主要操作と主要設定をまとめる領域である。

### 6.2 配置する主な要素

MS16 時点では、以下の要素を想定する。

```text
- TEXT読込
- WAV/MP3読込
- 解析
- VMD保存
- 再生
- 停止
- Zoom In
- Zoom Out
- Reset Zoom
- プリセット選択
- モーフ最大値
- 開口保持
- 閉口スムーズ
```

### 6.3 表示方針

* 主要操作はアイコン付きボタンでよい。
* 既存の操作導線を大きく変えない。
* `WAV読込` は MS17 の mp3対応を見据え、将来的に `WAV/MP3読込` として扱える配置にしておく。
* プリセット選択は MS20 以降で本格化するが、MS16時点で配置場所を確保しておく。
* モーフ最大値、開口保持、閉口スムーズは、当面は上部に残す。
* 将来的に詳細設定を右ペインへ移してもよいが、MS16では既存操作との連続性を優先する。

### 6.4 Out of Scope

MS16では以下は実装しない。

* プリセット編集本体
* モデル別プロファイル編集本体
* 詳細設定ダイアログの全面刷新
* ツールバーの過度な再設計

## 7. 左ペイン仕様

### 7.1 目的

左ペインは、入力情報の概要を表示する領域である。

ユーザーが以下を確認できることを目的とする。

* 現在読み込んでいる TEXT
* 現在読み込んでいる WAV / mp3
* テキスト概要
* ひらがな概要
* 母音列概要
* 音声情報

### 7.2 左ペインに表示する情報

MS16時点では、以下を想定する。

```text
入力情報:
  - TEXTファイル名
  - WAV / mp3 ファイル名

テキスト:
  - 原文TEXTの冒頭表示
  - 文字数

ひらがな:
  - ひらがな変換結果の冒頭表示
  - 文字数

母音列:
  - 母音列の冒頭表示
  - 母音数
  - 各母音の簡易カウント

音声情報:
  - ファイル名
  - サンプルレート
  - チャンネル数
  - ビット深度
  - 再生時間
  - ファイルサイズ
```

### 7.3 ひらがな編集の扱い

MS16時点では、左ペインにひらがな全文編集 UI を常設しない。

理由:

* 左ペインは入力概要を確認する場所であり、長文編集領域ではない
* 長文編集欄を常設すると、左ペインが圧迫される
* メイン画面の責務を、確認・可視化・情報表示に保つため
* 音声のみ入力やASR結果修正では、集中編集用のポップアップウィンドウの方が適している

将来的な方針:

```text
メイン画面:
  - 原文TEXTの概要表示
  - ひらがな概要表示
  - 母音列概要表示
  - 編集ボタンまたは確認ボタン

ポップアップ:
  - 認識テキスト編集
  - ひらがな編集
  - 変換結果確認
```

### 7.4 将来の編集フロー

将来的には以下の流れを想定する。

```text
原文テキスト
  ↓
自動変換ひらがな
  ↓
ユーザー修正ひらがな
  ↓
母音列再生成
  ↓
Preview / Info / Warning 更新
```

MS16では、この将来フローを妨げない左ペイン構成にする。

## 8. 中央ペイン仕様

### 8.1 目的

中央ペインは、`MMD_AutoLipTool` の中核表示領域である。

以下を表示する。

* 中央上: 波形表示
* 中央下: リッププレビュー

### 8.2 中央ペインの基本方針

MS16では、波形表示とリッププレビューの同期を重視する。

必須条件:

* 波形表示とリッププレビューの横軸を合わせる
* 表示開始・表示終了位置を一致させる
* 再生カーソルの位置を一致させる
* Zoom / Pan / Auto-follow の結果が両方に反映される
* 波形表示とリッププレビューの縦ガイド線が一致する

### 8.3 波形表示

波形表示は、音声の時間的な強弱を確認するための領域である。

表示内容:

```text
- 音声波形
- 時間軸
- 再生カーソル
- 現在再生時間
- Zoom / Viewport の反映
```

### 8.4 リッププレビュー

リッププレビューは、母音モーフ `あ / い / う / え / お` の変化を視覚化する領域である。

MS16では、現在のリボン型表示から、旧Qt/PySide版に近い以下の表示へ戻す。

```text
- 三角形
- 変形台形
- エンベロープ形状
- 多点制御形状
```

### 8.5 リボン表示からの復元方針

現在の wx 版 Preview は、母音イベントを横長のリボン状区間として表示している。

これは、発声区間の存在確認には使えるが、以下の情報を読み取りにくい。

* どこで口が開き始めるか
* どこで最大開口になるか
* どれくらい開口を維持するか
* どのように閉じるか
* `開口保持` / `閉口スムーズ` がどう反映されているか
* 同音母音や長音の谷・維持・減衰がどう表現されるか

MS16では、リッププレビューを VMD 出力形状に近い表示へ戻す。

### 8.6 Preview表示に必要な概念

Preview表示では、以下を扱えるようにする。

```text
- vowel
- source_event_index
- shape_kind
- frame_range
- value_range
- control_points
- start_zero
- top
- hold
- slope_mid
- valley
- end_zero
```

ただし、MS16では実編集は行わない。
あくまで表示と将来編集のための下地を整える。

### 8.7 Previewとwriterの関係

Preview は、writer の出力概念と大きく乖離してはならない。

避けること:

```text
- Preview 側だけが独自に形状を推測する
- Previewでは台形に見えるが、VMD出力では全く異なる
- writer の shape 契約を無視する
```

目指すこと:

```text
- Preview と writer が同じ、または近い shape 情報を参照する
- ユーザーが Preview で見た口形変化が、VMD出力の概念と一致する
- 将来の母音イベント編集に自然につながる
```

## 9. 右ペイン仕様

### 9.1 目的

右ペインは、情報表示・警告・選択イベント詳細・プリセット・モデルプロファイルを扱う領域である。

MS16時点では、右ペインの基本構造を確保することが目的であり、各タブの本格機能は後続MSで実装する。

### 9.2 右ペインのタブ構成

MS16では、以下のタブを用意する。

```text
- Info
- Warning
- 選択イベント
- プリセット
- モデルプロファイル
```

注意:

* 最初のタブ名は `Info` とする。
* `診断` というタブ名は使用しない。
* 診断情報は `Info` または `Warning` の中で扱う。
* 右ペインは、将来的にタブ追加できる構成にしておく。

### 9.3 Info タブ

Info タブは、現在の解析状態や基本情報を表示する場所である。

MS16時点では、以下のような placeholder または最小情報表示でよい。

```text
概要:
  - 音声時間
  - 総フレーム数
  - 推定モーフ数
  - 平均モーフ密度
  - 無音区間

現在位置:
  - 現在フレーム
  - 現在時刻
  - 現在の母音
  - 現在のモーフ
```

MS19以降では、出力診断レポートの内容をここへ統合する。

### 9.4 Warning タブ

Warning タブは、解析・生成・保存前の注意事項を一覧表示する場所である。

MS16時点では、枠または placeholder でよい。

将来的に表示する警告例:

```text
- TEXT と音声長が大きく不一致
- Whisper anchor が少ない
- even fallback が使用された
- 無音区間が多い
- 歌唱・楽曲音声の可能性
- モーフ数上限に近い
- 入力音声が長尺
- ASR認識結果が不足している
```

### 9.5 選択イベント タブ

選択イベントタブは、Preview 上で選択した母音イベントの情報を表示する場所である。

MS16時点では、選択情報表示の下地を用意する。

将来的な表示内容:

```text
- event_index
- source_event_index
- vowel
- start_frame
- peak_frame
- end_frame
- duration_frames
- peak_value
- shape_kind
- control_points
```

本格的な編集は MS21 以降で行う。

### 9.6 プリセット タブ

プリセットタブは、生成設定プリセットを表示・選択・編集するための場所である。

MS16時点では、枠または現在値表示でよい。

本格実装は MS20 以降とする。

将来的な内容:

```text
- プリセット名
- モーフ最大値
- 開口保持
- 閉口スムーズ
- 長音処理
- 同音母音処理
```

### 9.7 モデルプロファイル タブ

モデルプロファイルタブは、MMDモデルごとの数値設定を保存・再利用するための場所である。

MS16時点では、枠または将来予定表示でよい。

本格実装は MS22 以降とする。

注意:

* PMX読み込みはしない
* 3Dプレビューはしない
* モデル別の数値設定再利用に留める

将来的な内容:

```text
- profile_name
- morph_upper_limit
- closing_hold_frames
- closing_softness_frames
- default_preset
- notes
```

## 10. 下部ステータスバー仕様

### 10.1 目的

下部ステータスバーは、現在の処理状態や再生位置を簡潔に表示する領域である。

### 10.2 表示内容

MS16時点では、以下を想定する。

```text
- 解析状態
- VMD出力可否
- 処理時間
- 使用メモリ
- 入力TEXT文字数
- WAV / mp3 音声尺
- FPS
- 再生位置
- 現在フレーム / 総フレーム数
- 音量スライダー
```

### 10.3 Warningとの責務分離

ステータスバーは、短い状態表示に限定する。

詳細な警告や診断情報は右ペインに表示する。

```text
ステータスバー:
  短い状態表示

右ペイン:
  詳細情報
  Warning
  出力診断
  選択イベント情報
```

## 11. ポップアップ編集方針

### 11.1 基本方針

長文編集や集中確認が必要な操作は、メイン画面に常設せず、ポップアップウィンドウで扱う。

対象:

```text
- 認識テキスト確認
- ひらがな編集
- 母音変換前の確認
- 将来的な詳細設定
```

### 11.2 ひらがな編集ポップアップ

将来的なひらがな編集は、以下のようなポップアップを想定する。

```text
- 元テキスト表示
- ひらがな編集欄
- 母音列プレビュー
- 文字数表示
- OK
- Cancel
- 自動再変換
```

### 11.3 モーダル / 非モーダル

初期実装では、ひらがな編集はモーダルダイアログでよい。

理由:

* 編集中にメイン画面の状態と競合しにくい
* 実装が分かりやすい
* Undo / Redo の境界を切りやすい
* 確定時に母音列とPreview更新を明確にできる

## 12. 将来拡張との関係

### 12.1 MS17との関係

MS17では、mp3対応とMMD用WAV同時出力を行う。

MS16のGUIでは、以下を先に考慮しておく。

* `WAV/MP3読込` へ拡張しやすいボタン配置
* 音声情報欄で WAV / mp3 の両方を扱える表示
* 将来のMMD持ち込み用WAV出力情報を表示できる余地

### 12.2 MS18との関係

MS18では、音声のみ入力とASR抽象化を行う。

MS16のGUIでは、以下を先に考慮しておく。

* 左ペインに認識テキスト / ひらがな / 母音列の概要を置けること
* 詳細編集はポップアップで扱えること
* 右ペインに ASR 情報や Warning を表示できること

### 12.3 MS19との関係

MS19では、Info / Warning / 出力診断を本格化する。

MS16のGUIでは、以下を先に考慮しておく。

* 右ペインに Info タブを設ける
* Warning タブを設ける
* 出力診断レポートを将来表示できる領域を確保する

### 12.4 MS20との関係

MS20では、連続同音母音・長音処理とプリセット基盤を行う。

MS16のGUIでは、以下を先に考慮しておく。

* Preview が変形台形 / エンベロープ形状を表示できること
* 右ペインにプリセットタブを確保すること
* 上部にプリセット選択領域を置けること

### 12.5 MS21との関係

MS21では、母音イベント単位の軽微編集を行う。

MS16のGUIでは、以下を先に考慮しておく。

* Preview 図形と母音イベントが対応づくこと
* source_event_index 等の metadata を持つこと
* 選択イベントタブに情報を流し込めること
* 将来の hit-test に必要な描画情報を保持できること

### 12.6 MS22との関係

MS22では、発音単位スロープ、セッション保存、モデル別プロファイルを扱う。

MS16のGUIでは、以下を先に考慮しておく。

* モデルプロファイルタブを確保する
* セッション保存時に必要な状態表示ができる余地を残す
* 調整レイヤーを受け止めるGUI配置にしておく

## 13. 責務境界

### 13.1 MMD_AutoLipToolの責務

MS16 GUI は、以下の責務を持つ。

```text
- リップVMD生成前の入力確認
- 波形確認
- 口形カーブの確認
- 生成結果の事前確認
- 軽微編集へ進むための下地
- 診断・Warning表示の下地
```

### 13.2 MMD本体の責務

以下は MMD 側の責務として残す。

```text
- モデル上での最終見た目確認
- 他モーションとの干渉確認
- 表情全般の調整
- カメラ / ボーン / 表情の総合編集
- 最終演出判断
```

### 13.3 入れないもの

本GUIでは、以下を扱わない。

```text
- PMXモデル読み込み
- 3Dプレビュー
- MMD風の表情タイムライン編集
- カメラ / ボーン / 表情全般のVMD編集
- VMD読み込み後の汎用編集
- DAW的な波形編集
- MMDプロジェクト管理
```

理由:

* 本ツールは MMD本体の代替ではない
* Whisper 等のASR処理だけでもリソースを消費する
* Pythonベースで3D表示を導入すると、依存・処理負荷・配布コストが大きくなる
* MS16の目的は、リップ生成の確認と将来編集基盤であり、DCC統合ではない

## 18. 要約

MS16 GUI の目的は、単なる見た目の修正ではない。

MS16では、現在のリボン型Previewを旧Qt/PySide版に近い変形台形表示へ戻し、同時に将来拡張を見据えた GUI レイアウトを固定する。

特に重要なのは以下である。

```text
- 中央に波形とPreviewを大きく置く
- 波形とPreviewの時間軸を完全に同期する
- 右ペインに Info / Warning / 選択イベント / プリセット / モデルプロファイルを置く
- 長文編集はメイン画面に常設せず、将来ポップアップで扱う
- MMD本体の責務を侵食しない
- ベータ版リリース後にGUIが大きく変わらない土台を作る
```

この仕様により、MS17以降の mp3対応、音声のみ入力、出力診断、プリセット、母音イベント編集、セッション保存へ、画面構成を大きく変えずに段階的に進める。
