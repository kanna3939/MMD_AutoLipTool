## 2. 文書目的

本書は、`MMD_AutoLipTool` における安全性基準を定義する文書である。

対象とする安全性は、主に以下である。

- 入力ファイル安全性
- 音声変換安全性
- 設定永続化安全性
- VMD出力安全性
- MMD用WAV出力安全性
- GUI操作安全性
- 高負荷入力への耐性
- 外部ツール利用時の安全性
- 配布物・onefile実行時の安全性
- エラー表示・ログ・問い合わせ時情報の扱い

本書は、商用ソフトウェア水準の完全なセキュリティ保証を目的とするものではない。

本書の目的は、Windows向け個人制作フリーソフトとして、利用者の通常利用において以下を満たすための基準を定めることである。

- 異常入力で容易にクラッシュしない
- 壊れた設定で起動不能にならない
- 入力内容を任意実行しない
- 高負荷入力で無制限に暴走しない
- 不完全または不正な出力を成功扱いしない
- 処理失敗後も可能な限り再実行可能状態へ戻る
- 配布物に含めるべき説明・ライセンス表示を欠落させない

本書は、Codex による実装、レビュー、テスト項目作成、ドキュメント整備時の安全性基準として扱う。

## 6. 想定安全性レベル

本ツールの安全性目標は、一般的な Windows 向け個人制作フリーソフトとして妥当な水準とする。

## 7. TEXT入力安全性

### 7.1 基本方針

TEXT入力は、MMD用リップモーション生成の原稿として扱う。

`.txt` 拡張子であっても、拡張子のみでは信用しない。

本ツールは、入力テキストを以下のように扱う。

* 文字列データとして読む
* Pythonコードとして評価しない
* コマンドとして実行しない
* スクリプトとして解釈しない
* 不正または仕様外の内容は、警告またはエラーとして扱う

### 7.2 想定する通常入力

以下は通常入力として許容する。

* 日本語台詞文
* 字幕文
* VOICEROID / A.I.VOICE 等の音声合成原稿
* 人声の文字起こし文
* ひらがな
* カタカナ
* 漢字
* 英数字
* 一般的な句読点・記号
* 半角スペース
* 全角スペース
* 改行

### 7.3 許容する代表的な記号

通常利用の範囲では、以下を許容対象とする。

```text
、。！？…・ー
（）「」『』【】
, . ! ? : ; / -
```

上記以外のUnicode通常文字についても、音声原稿として自然に現れる範囲では許容してよい。

ただし、読込可能であることと、リップ生成に適することは同一ではない。

### 7.4 文字コード方針

基本文字コードは UTF-8 とする。

UTF-8で読めない場合、代表的な文字コードを順次試行してよい。

試行候補:

1. UTF-8
2. Shift_JIS
3. UTF-16

注意:

* 文字コード判定に失敗した場合は明示エラーとする
* 文字化けした内容を黙って成功扱いしない
* 読込成功後も、内容が入力仕様に適合するか確認する

### 7.5 入力前正規化

TEXT入力に対しては、検証前または検証時に以下の正規化を行ってよい。

* 改行コード `\r\n` および `\r` を内部的に `\n` へ統一する
* タブ `\t` を半角スペースへ置換する
* UTF-8 / UTF-16 の BOM を除去して扱う
* 行頭・行末の不要空白を必要に応じて除去する
* 通常の連続空白は原則として保持する

### 7.6 制御文字の扱い

* 改行は許容する
* タブは空白へ正規化する
* 改行・タブ以外の制御文字は原則不許可とする
* 少量混入時は除去と警告で処理してよい
* 多量混入時は読込エラーとする

基準:

| 条件 | 扱い |
| ------------------ | ---------- |
| 改行・タブ以外の制御文字 1〜4文字 | 除去して警告してよい |
| 改行・タブ以外の制御文字 5文字以上 | 読込エラー |

### 7.7 文字数・行長上限

TEXT入力の上限は以下とする。

| 項目 | 上限 / 条件 | 扱い |
| -------- | -------- | ---- |
| 総文字数 | 5,000文字超 | エラー |
| 1行長 | 500文字超 | 警告対象 |
| 1行長 | 2,000文字超 | エラー |
| 同一記号連続 | 100文字超 | 警告対象 |
| 記号のみの長大行 | 300文字超 | エラー |

これらの値は、セキュリティ上の絶対限界ではなく、Windows向け個人制作ツールとして応答性と安定性を保つための運用上限である。

### 7.8 上限超過時の扱い

上限超過時は、原則として即エラー停止とする。

以下は行わない。

* 黙って切り詰める
* 警告だけ出して処理を続行する
* 処理途中で一部だけ無視して成功扱いする

### 7.9 期待動作

TEXT入力の異常時は以下を満たすこと。

* 利用者に分かる形で失敗を通知する
* 処理実行へ進ませない
* 古い解析結果を新しい成功結果として扱わない
* 失敗後も再度ファイル選択できる状態へ戻る
* アプリ全体は継続利用可能であることを優先する

## 8. 音声入力・解析用WAV安全性

### 8.1 基本方針

入力音声はユーザーが選択する音声ファイルであり、解析処理では内部で生成した解析用WAVを音声正本として扱う。

`.wav` 拡張子であっても、拡張子のみでは信用しない。

入力音声および解析用WAVでは、少なくとも以下を確認する。

* RIFF / WAVE ヘッダ
* PCM形式
* bit深度
* sampling rate
* チャンネル数
* データ長整合
* 音声長

### 8.2 現行対応形式

現行の基本処理対象は以下とする。

* PCM WAV
* 16bit
* 44.1kHz または 48kHz

チャンネル数は、現行実装・変換処理の仕様に従う。

### 8.3 非対応または直接処理対象外の形式

現行版において、以下は直接処理対象外とする。

* mp3
* mp4
* m4a
* ogg
* flac
* 非PCM WAV
* ヘッダ破損WAV
* 長さ不整合WAV
* 仕様外のbit深度・sampling rate のWAV

ただし、MS17以降で wav / mp3 / m4a 入力に対応する場合は、入力音声を直接解析するのではなく、安全な変換処理を経て解析用WAVを生成し、その解析用WAVに対して本章のWAV検証を適用する。

### 8.4 音声長上限

音声長上限は以下とする。

| 項目 | 上限 |
| ----- | --- |
| 音声長 | 15分 |

15分を超える場合は、原則としてエラー停止とする。

この値は、Windows向け個人制作ツールとして、解析時間・メモリ使用量・GUI応答性を守るための運用上限である。

### 8.5 WAV読込失敗時の扱い

WAV読込失敗時は以下を満たすこと。

* GUI上で明示通知する
* 処理実行へ進ませない
* 既存の正常な入力状態と混同しない
* 失敗したWAVを最近使ったファイル履歴へ追加するかは、実装方針に従う
* アプリ全体は継続利用可能とする

### 8.6 期待動作

音声入力または解析用WAVの異常時は以下を満たすこと。

* ヘッダ不正時は拒否する
* 形式不正時は拒否する
* データ長不整合時は拒否する
* 読めたように見える破損ファイルをそのまま処理継続しない
* 古い解析結果を新しい入力の結果として扱わない

## 9. 音声入力・音声変換安全性

### 9.1 位置づけ

wav / mp3 / m4a 入力対応と音声変換は、MS17の設計・実装対象である。

MS17-B6時点では、wav / mp3 / m4a 入力とFFmpegによる解析用WAV変換は実装済み、MMD用WAV出力は予定または設計対象として扱う。

MMD用WAV出力を、MS17-B6時点の実装済みまたは検証済みとして記述してはならない。

### 9.2 基本方針

mp3 は直接解析対象とはしない。

wav / mp3 / m4a 入力に対応する場合は、以下の流れを原則とする。

1. mp3ファイルを選択する
2. 入力ファイルの存在・拡張子・サイズ等を確認する
3. ffprobe 等でメタ情報を確認する
4. FFmpeg 等で安全に WAV へ変換する
5. 解析用WAVに対して WAV入力安全性検証を行う
6. 検証を通過したWAVのみ、既存処理へ渡す

### 9.3 変換前検証

音声入力時は、変換前に少なくとも以下を確認する。

* ファイルが存在する
* 通常ファイルである
* サイズが極端に大きすぎない
* パスが読み取り可能である
* 拡張子とメタ情報が大きく矛盾していない
* ffprobe で音声ストリームを確認できる
* 音声長が上限を超えていない

### 9.4 変換後検証

解析用WAVは、WAV入力と同じ基準で検証を受ける。

変換成功と解析可能は同義ではない。

変換後に確認すること:

* 出力ファイルが存在する
* ファイルサイズが0ではない
* RIFF / WAVE として妥当である
* PCM形式である
* 16bitである
* 44.1kHz または 48kHz である
* データ長が整合している
* 音声長が上限内である

### 9.5 変換失敗時の扱い

変換失敗時は以下を満たすこと。

* GUI上で明示通知する
* VMD生成へ進まない
* 変換途中の不完全ファイルを残さない
* 一時ファイルを可能な限り削除する
* 失敗後も再選択・再実行可能状態へ戻す
* 例外の内部詳細をそのまま常時表示しない

### 9.6 変換に使う一時ファイル

一時ファイルを使う場合は以下を守る。

* 一時ファイル名は衝突しにくいものにする
* ユーザー入力を未検証のままファイル名として使わない
* 処理失敗時は可能な限り削除する
* onefile の一時展開領域を永続保存先にしない
* MMD用WAVとして残すファイルと内部一時ファイルを混同しない

### 9.7 変換時の上限

wav / mp3 / m4a 入力対応時も、音声長上限は原則としてWAVと同等に扱う。

| 項目 | 上限 |
| ------- | --- |
| 変換対象音声長 | 15分 |

上限の変更が必要な場合は、MS17以降の実装計画で明示的に判断する。

## 10. MMD用WAV出力安全性

### 10.1 位置づけ

MMD用WAV出力は、MS17-B7以降の設計対象である。

本書作成時点では、実装済みとして扱わない。

### 10.2 基本方針

mp3 / m4a などの非WAV入力から処理する場合、MMDで読み込めるWAVを専用導線から出力することを検討対象とする。

このWAV出力は、内部処理用一時WAVとは区別する。

| 種別 | 目的 |
| ------- | --------------------- |
| 内部変換WAV | 解析処理へ渡すための中間データ |
| MMD用WAV | 利用者がMMDに読み込むための出力ファイル |

### 10.3 出力先方針

MMD用WAVの出力先は、VMD出力先と関連づけることを基本とする。

想定方針:

* VMDと同じフォルダに出力する
* 入力ファイル名を元に安全な出力名を作る
* 拡張子は `.wav` とする
* 同名ファイルが存在する場合は上書き確認を行う
* VMD保存とWAV保存の順序は、実装計画で明示する

### 10.4 上書き確認

MMD用WAVの出力先に同名ファイルが存在する場合は、利用者確認を挟む。

黙って上書きしてはならない。

### 10.5 不完全出力の扱い

MMD用WAV出力に失敗した場合は、以下を満たすこと。

* 不完全なWAVを可能な限り削除する
* VMD出力とWAV出力のどちらが失敗したか明示する
* 一方のみ成功した場合の扱いをGUI上で明示する
* 再実行可能状態へ戻す

### 10.6 VMDとWAVの整合

wav / mp3 / m4a 入力からVMDとMMD用WAVの両方を出力する場合、VMDが参照するタイミングとMMD用WAVの長さ・内容が対応している必要がある。

確認すべき観点:

* 解析に使ったWAVとMMD用WAVが同じ変換結果に基づいている
* 音声長が一致している
* 途中失敗時に古いWAVと新しいVMDを混同しない
* 再変換時に古い出力を誤って成功扱いしない

## 11. 高負荷入力・巨大ファイル対策

### 11.1 基本方針

高負荷入力は、悪意の有無に関係なく、フリーズ・無応答・異常終了の主要因として扱う。

対象:

* 巨大TXT
* 長大な1行
* 巨大WAV
* 長時間音声
* 巨大mp3
* 高密度波形表示が必要な入力
* 極端に細かいPreviewイベント
* キーフレーム数が過大になる入力

### 11.2 動作方針

* 読込前または読込直後に上限確認を行う
* 上限超過時は明示エラーとする
* 波形描画は表示用の要約データを使用してよい
* Preview描画は表示範囲に応じて描画量を制御してよい
* UIを長時間無応答状態のまま放置しない
* 時間がかかる処理には処理中表示を出す
* 必要に応じてキャンセル導線を設ける

### 11.3 GUI応答性

処理時間が長い場合は、以下のいずれか、または複数を行う。

* 処理中表示
* 進捗表示
* フェーズ表示
* 長時間処理警告
* 操作抑止表示
* キャンセル導線
* 処理完了後の明示通知

### 11.4 失敗時の復帰

高負荷入力で処理に失敗した場合でも、以下を満たすこと。

* Busy状態を解除する
* 無効化したUI操作を復元する
* 処理中ダイアログを閉じる
* 古い成功結果と失敗結果を混同しない
* 再実行可能状態へ戻す

## 12. 任意実行・危険導線の禁止

### 12.1 入力評価実行禁止

入力ファイル内容を、コード・式・命令として評価実行してはならない。

禁止対象例:

* `eval`
* `exec`
* 入力文字列をPython式として評価する処理
* 入力文字列をスクリプトとして実行する処理
* 入力文字列をテンプレート経由で任意実行へつなげる処理

### 12.2 シェル実行への連動禁止

入力内容を、そのまま外部コマンド・シェル・OS実行へ連動させてはならない。

禁止事項:

* 入力テキストをコマンドとして実行する
* 入力ファイル名を未検証のままコマンド文字列へ連結する
* ユーザー指定値をそのまま `shell=True` のコマンドへ渡す
* 任意コマンド入力欄を設ける
* 外部スクリプトを任意指定して実行させる

### 12.3 本ツールの前提

本ツールはローカルGUI変換ツールである。

入力内容に基づく任意実行機能は要件上不要である。

したがって、任意実行導線は原則として禁止する。

## 13. 管理済み外部ツール呼び出し方針

### 13.1 位置づけ

MS17以降で wav / mp3 / m4a 入力や音声変換を扱う場合、FFmpeg / ffprobe を利用する。

そのため、本書では外部コマンドを全面禁止とはしない。

禁止するのは、任意実行・未検証入力のシェル連結・危険なコマンド導線である。

管理されたFFmpeg / ffprobe呼び出しは、条件付きで許可する。

### 13.2 許可条件

FFmpeg / ffprobe を呼び出す場合は、以下を満たすこと。

* アプリが管理する固定パス、または明示的に検出・確認したパスを使う
* 実行ファイル名をユーザー入力から直接決めない
* 引数は文字列連結ではなく配列で渡す
* `shell=True` を前提にしない
* 入力ファイルパスと出力ファイルパスを個別引数として渡す
* タイムアウトを設定する
* 終了コードを確認する
* 標準出力・標準エラーの扱いを制御する
* 変換後ファイルを別途検証する
* 失敗時に不完全出力を削除する

### 13.3 禁止事項

以下は禁止する。

* 任意のコマンドラインをユーザーに入力させて実行する
* 入力テキストの内容をコマンド引数へ流用する
* パスや引数を1本のシェル文字列として組み立てる
* 失敗した変換結果を成功扱いする
* FFmpegの存在確認だけで変換成功とみなす
* 解析用WAVの検証を省略する

### 13.4 FFmpeg同梱有無

FFmpegを配布ZIPに同梱するかどうかは、配布方針とライセンス確認に基づいて決定する。

本書では、同梱を確定事項として扱わない。

同梱する場合は、少なくとも以下を確認する。

* FFmpeg配布元
* FFmpegビルドのライセンス
* GPL / LGPL の区分
* 同梱するバイナリ
* upstream license texts
* THIRD_PARTY_LICENSES.md への記載
* NOTICE への記載
* 配布ZIP内の配置

## 14. 設定永続化安全性

### 14.1 基本方針

設定永続化では、壊れた設定で起動不能にしないことを優先する。

設定ファイルは信頼境界の外にあるものとして扱い、復元時に妥当性確認を行う。

### 14.2 破損時方針

設定ファイルが破損している場合は、以下を満たすこと。

* 破損設定を無理に読み込まない
* 安全な既定値で起動する
* 起動不能にしない
* 必要に応じて利用者へ警告する
* 再保存時は正常な設定として保存する

### 14.3 異常値方針

保存済み設定値は無条件で採用しない。

復元時に範囲確認・妥当性確認を行い、不正値は既定値へ戻す。

対象例:

* テーマ値
* ウィンドウサイズ
* ウィンドウ位置
* splitter比率
* 最近使ったファイル履歴
* 保存先フォルダ履歴
* パラメータ値
* 音声関連設定
* 将来追加される変換関連設定

### 14.4 設定保存先

設定保存先は、現行実装方針に従う。

exeと同じ場所に保存する方針を採る場合は、以下を考慮する。

* exe配置先が書き込み可能とは限らない
* Program Files 配下などでは保存失敗する可能性がある
* onefile実行時の一時展開領域を保存先にしてはならない
* 保存失敗時は警告し、アプリ継続利用を優先する

### 14.5 保存失敗時方針

設定保存に失敗した場合は、以下を満たすこと。

* 警告ダイアログまたは明示的なエラー表示を行う
* 保存失敗を黙って無視しない
* アプリ本体は可能な限り継続利用可能にする
* 保存できなかった設定は次回起動時に復元されないことを明示する

### 14.6 保存失敗後の制限範囲

保存失敗後は、原則として保存処理のみを制限対象とする。

* UI上の設定変更は、そのセッション中に限り反映してよい
* 保存できないことは明示する
* 次回起動時には、再度保存可能か判定してよい
* 保存失敗を理由に音声解析やVMD出力まで停止する必要はない

### 14.7 最近使ったファイル履歴

最近使ったファイル履歴は保存対象としてよい。

方針:

* 履歴件数上限は10件とする
* 存在しない履歴パスは起動時または表示時に整理してよい
* 履歴パスが読めない場合は安全にスキップする
* 履歴からの読込失敗時は明示通知する
* 失敗した履歴を無条件に残し続けない

### 14.8 重要設定

本ツールにおける重要設定は、少なくとも以下とする。

* テーマ
* ウィンドウサイズ
* ウィンドウ位置
* splitter比率
* 最後に使った保存先
* 音声変換関連設定が追加された場合の変換方針

保存タイミングは、実装計画に従う。

ただし、重要設定の都度保存と、終了時まとめ保存を混在させる場合は、どの設定がどちらに属するかを明示する。

## 15. VMD出力安全性

### 15.1 基本方針

VMD出力では、不正確な成功より安全な失敗を優先する。

入力妥当性が崩れた場合、出力を継続しない。

### 15.2 出力停止条件

以下のいずれかに該当する場合、VMD出力を中止する。

* TEXT入力妥当性が崩れた場合
* 音声入力または解析用WAVの妥当性が崩れた場合
* mp3変換結果が妥当でない場合
* 解析結果が存在しない場合
* 解析結果が現在の入力と対応していない場合
* 処理継続で安全な結果が保証できない場合
* モーフキーフレーム総数が上限を超える場合
* 出力先へ書き込めない場合
* 上書き確認で利用者が拒否した場合

### 15.3 キーフレーム数上限

| 項目 | 上限 |
| ----------- | ------ |
| モーフキーフレーム総数 | 22,000 |

上限超過時は即エラー停止とする。

自動切り詰めや黙った省略は行わない。

### 15.4 上書き方針

出力先に同名ファイルが存在する場合は、利用者確認を挟む。

* 黙って上書きしない
* 上書き拒否時は処理を中止する
* 中止時はエラーではなくキャンセル扱いとしてよい
* ただし、保存完了とは扱わない

### 15.5 一時出力と置換

不完全なVMDを残さないため、可能であれば一時ファイルへ書き出し、成功後に目的ファイルへ置換する。

ただし、実装方式は既存writerの制約に従う。

失敗時は以下を満たすこと。

* 不完全な出力ファイルを可能な限り削除する
* 既存の正常ファイルを破壊しない
* 失敗した保存を成功扱いしない
* 再保存可能状態へ戻す

### 15.6 解析結果と入力の対応

VMD保存時は、解析結果が現在の入力TEXT / 音声ファイル、および内部の解析用WAVと対応していることを確認する。

以下のような場合は、解析結果を無効化する。

* TEXTを再読込した
* 音声ファイルを再読込した
* 入力音声の変換元が変わった
* 解析用WAVが再生成された
* 解析に関係するパラメータが変更された
* 解析が失敗した
* キャンセルされた
* 古いworker結果が遅れて返ってきた

## 16. パス・ファイルシステム安全性

### 16.1 基本方針

Windows環境では、日本語パス、空白を含むパス、長いパス、特殊文字を含むパスの存在を前提とする。

### 16.2 対応方針

* パス処理には `pathlib` 等の安全なAPIを使う
* 文字列連結だけでパスを作らない
* 日本語パスを想定する
* 空白を含むパスを想定する
* 読み取り不可・書き込み不可の場合は明示エラーとする
* ネットワークドライブや外付けドライブの消失に備える
* 存在しない履歴パスを安全に扱う

### 16.3 禁止事項

以下は禁止する。

* パス異常時に未処理例外のまま停止する
* 存在しない履歴パスを無期限に放置する
* ユーザー入力を未検証のまま一時ファイル名へ使う
* 出力先が不明なまま保存成功扱いする
* onefileの一時展開先を設定やユーザー出力の保存先にする

### 16.4 長いパス

長いパスは可能な限り対応する。

ただし、OS設定や外部ライブラリの制約により処理不能な場合は、明示エラーとして扱う。

## 19. wxPython GUI 操作安全性

### 19.1 基本方針

wxPython GUIでは、状態競合と多重実行を避ける。

GUI状態は、可能な限り以下を分離して扱う。

* 入力読込状態
* 解析結果有効状態
* 処理中状態
* 再生可能状態
* 再生中状態
* 保存可能状態
* 表示可能状態

### 19.2 処理中操作

処理中は、状態破壊につながる操作を抑止する。

対象例:

* TEXT再読込
* 音声ファイル再読込
* 処理再実行
* VMD保存
* MMD用WAV保存
* パラメータ変更
* Recent Files からの別ファイル読込
* アプリ終了

ただし、キャンセルや中止など、安全に設計された操作は許可してよい。

### 19.3 Busy状態

Busy状態では以下を満たすこと。

* 多重実行を防ぐ
* 関連ボタンを無効化する
* 処理中表示を行う
* 完了時に必ずBusy状態を解除する
* 失敗時にもBusy状態を解除する
* キャンセル時にもBusy状態を解除する
* 遅れて返る古い処理結果を現在状態へ反映しない

### 19.4 解析キャンセル

解析キャンセルを提供する場合は、以下を満たすこと。

* キャンセル要求をUIから送れる
* キャンセル後に遅れて返る結果を破棄できる
* キャンセル後に古い結果を保存可能状態にしない
* キャンセル後にUIを再実行可能状態へ戻す

### 19.5 再生操作

再生操作では以下を満たすこと。

* 再生可能な音声がない場合はPlayできない
* 再生中は必要な操作を制限する
* Stop後は再生中状態を解除する
* 再生位置表示と内部状態が破綻しない
* 音声読込失敗時に古い音声を再生対象として扱わない

### 19.6 Waveform / Preview表示

波形表示とPreview表示では以下を満たすこと。

* 入力読込失敗時に古い表示を成功結果として扱わない
* 解析結果無効化時にPreviewをクリアまたは無効表示にする
* 表示範囲外のデータで描画エラーを起こさない
* 高倍率ズーム時にも描画処理が破綻しない
* テーマ変更時に視認性が著しく崩れない

### 19.7 Recent Files

Recent Files からの読込では以下を満たすこと。

* パスが存在しない場合は安全に失敗する
* 読込失敗時に古い入力状態を破壊しない
* counterpart auto-load が失敗してもアプリ全体を落とさない
* 履歴更新のタイミングは実装方針に従う

### 19.8 アプリ終了

処理中にアプリを閉じる場合は、以下を考慮する。

* 処理中であることを利用者へ示す
* 中止して終了するか、継続するかを確認する
* 強制終了により不完全出力が残らないようにする
* 終了時保存に失敗した場合は可能な範囲で通知する

## 20. 配布・onefile・Release ZIP 安全性

### 20.1 基本方針

通常利用者には、GitHub Releases に添付する実行用ZIPを案内する。

GitHubが自動生成する `Source code (zip)` / `Source code (tar.gz)` は、通常利用者向けの実行ファイルではない。

### 20.2 実行用ZIP

実行用ZIPには、少なくとも以下を含める。

* `MMD_AutoLipTool.exe`
* `readme_mmdautolip.txt`
* `LICENSE`
* `NOTICE`
* `THIRD_PARTY_LICENSES.md`

FFmpegを同梱する場合は、必要なライセンス文書やupstream license textsも含める。

### 20.3 Source code ZIP との違い

配布説明では、以下を明確にする。

| 種別 | 対象利用者 | 内容 |
| ------------------ | ----- | ---------------- |
| 実行用ZIP | 通常利用者 | exe と説明書・ライセンス文書 |
| Source code ZIP | 開発者 | ソースコード一式 |
| Source code tar.gz | 開発者 | ソースコード一式 |

通常利用者には実行用ZIPを案内する。

### 20.4 onefile時の注意

PyInstaller onefileでは、実行時に一時展開が発生する。

以下を守る。

* 一時展開先を永続保存先として扱わない
* 設定ファイルやユーザー出力を一時展開先に保存しない
* exe同階層に保存する設計の場合、書き込み不可に備える
* 保存失敗時は明示通知する
* ウイルス対策ソフトによる初回起動遅延や検査を考慮する

### 20.5 ライセンス表示

配布時には、少なくとも以下を同梱または明示する。

* 自作部分のライセンス
* 利用ライブラリのライセンス
* FFmpeg等の外部バイナリを含む場合のライセンス
* 免責事項
* 問い合わせ先
* GitHubリポジトリURL

### 20.6 FFmpeg同梱時の追加注意

FFmpegを同梱する場合は、以下を確認する。

* 配布するFFmpegビルドのライセンス
* GPL / LGPL の区分
* static / shared の区分
* 同梱ファイル一覧
* ライセンス文書の同梱
* THIRD_PARTY_LICENSES.md の更新
* NOTICE の更新
* Release ZIP 内での配置

FFmpeg同梱が未確定の場合は、同梱済みと断定してはならない。

## 22. MS17以降の追加確認観点

MS17以降で wav / mp3 / m4a 対応、FFmpeg利用、MMD用WAV出力を実装する場合、以下を確認する。

### 22.1 wav / mp3 / m4a 入力

* mp3ファイルを直接解析対象にしていないか
* 変換前にファイル存在・サイズ・メタ情報を確認しているか
* ffprobe失敗時に安全に停止できるか
* 音声長上限を確認しているか
* 解析用WAVをWAV入力と同じ基準で検証しているか
* 変換失敗時に古いWAVを誤って使わないか

### 22.2 FFmpeg / ffprobe

* 管理されたパスから呼び出しているか
* `shell=True` 前提になっていないか
* 引数配列で呼び出しているか
* タイムアウトがあるか
* 終了コードを確認しているか
* 標準エラーを適切に扱っているか
* 変換後ファイル検証を行っているか
* 不完全ファイルを削除しているか

### 22.3 MMD用WAV出力

* 解析用WAVとMMD用WAVを区別しているか
* VMDとWAVの出力先が分かりやすいか
* 同名上書き時に確認が入るか
* WAVのみ失敗、VMDのみ失敗、一方のみ成功の扱いが定義されているか
* 失敗時に不完全ファイルを残さないか
* 利用者にどのファイルをMMDへ読み込むべきか案内できるか

### 22.4 GUI

* mp3読込中に多重実行できないか
* 変換中に別ファイルを読めないか
* 変換失敗後にUIが復帰するか
* 変換成功後に解析可能状態へ遷移するか
* 解析用WAVと元音声ファイルの対応が崩れないか
* Recent Filesで入力音声ファイルと解析用WAVの扱いが破綻しないか

### 22.5 配布

* 実行用ZIPに必要文書が含まれているか
* Source code ZIPと実行用ZIPの違いを説明しているか
* FFmpeg同梱有無が説明と一致しているか
* FFmpeg同梱時にライセンス文書が不足していないか
* onefileの一時展開先を保存先として扱っていないか

## 23. 旧文書との関係

旧 `Security_Safety_Specification.md` は、Ver0.3.x 時点の安全仕様履歴として扱う。

旧文書に含まれていた以下の要素は、本書では現行前提として扱わない。

* Codex 前提
* Ver0.3.5.6 にて全て実装済みという断定
* mp3を恒久的な非対応形式として扱う記述
* 外部コマンドを全面禁止と読める記述
* Qt / PySide6 時代の前提に依存する記述

旧文書の安全思想のうち、以下は本書へ継承する。

* 異常入力でクラッシュしない
* 壊れた設定で起動不能にしない
* 巨大入力で暴走しない
* 不正確な出力を成功扱いしない
* 入力内容を評価実行しない
* GUI上で安全に失敗する
* 処理失敗後も再実行可能状態へ戻す

旧文書は、必要に応じて以下のような退避先で保存する。

```text
docs/_old/Security_Safety_Specification_legacy_ver0_3.md
```
