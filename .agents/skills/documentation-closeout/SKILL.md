# Documentation closeout

適用される`AGENTS.md`の権限・初動・検証規則に従い、ユーザーが限定した対象や禁止操作を越えない。
以下はこのSkillを使う作業の手順であり、タスク全体に別の承認工程を追加しない。対象・前提が変わっていない取得済みの証拠は再利用する。

## Workflow

1. 更新依頼と対象範囲を確認し、現在の差分、実装、テスト結果、手動確認結果から利用可能な関連証拠を集める。closeout判断がある場合は記録し、通常の文書更新に新たな完了判断を要求しない。
2. README、変更履歴、設計文書、進捗文書など、各文書の役割と更新対象を確認する。
3. `implemented`、`verified`、`unverified`、`planned`、`deferred`、`out of scope`を区別する。
4. 依頼範囲内で、矛盾の修正、不足する説明・検証記録・残課題の補完、到達状態の同期を最小限行う。履歴的記述は、現在状態と誤認されない限り保持する。
5. 更新対象と関連文書の間で、該当する版数、日付、状態、対象範囲、テスト数、残課題を照合する。
6. 差分を再読し、未実装機能の完了扱い、過大な検証主張、無関係な文書変更がないことを確認する。

## Boundaries

- ユーザーが明示したcloseout判断を尊重するが、確認できない技術的事実はユーザー判断と実測結果を分けて記載する。
- コード、テスト、ビルド設定を変更しない。
- 実行していないテストや手動操作を成功扱いにしない。

## Output

確認した証拠、更新文書、同期した状態、未検証事項、残課題を報告する。
