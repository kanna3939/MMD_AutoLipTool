# Repository state inspection

適用される`AGENTS.md`の権限・初動・検証規則に従い、ユーザーが限定した対象や禁止操作を越えない。
以下はこのSkillを使う作業の手順であり、タスク全体に別の承認工程を追加しない。対象・前提が変わっていない取得済みの証拠は再利用する。

## Workflow

1. 対象に適用される`AGENTS.md`を確認し、その初動規則に従って索引と必要な正本を読む。対象限定時の例外も適用する。
2. `git status`、現在ブランチ、最近の履歴、remote/trackingの必要範囲を一つずつ確認する。
3. tracked、modified、staged、untrackedを区別し、既存変更をユーザー所有として扱う。
4. 構成や入口の確認が依頼範囲に含まれる場合は、`README*`、`pyproject.toml`、ロックファイル、CI、`src/`、`tests/`などから必要なものを選び、実在する採用ツールと主要入口を特定する。
5. 現在有効な設計・計画文書だけを対象作業に応じて読む。巨大履歴や古い計画を無差別に読まない。
6. 実装済み、検証済み、変更中、計画、将来候補、未確認を分ける。
7. 文書とコードの不一致、危険な作業ツリー、テスト入口不明、依存・環境のずれを重要度付きで報告する。

## Boundaries

- 読み取り専用で実施し、編集、stage、commit、stash、restore、checkoutを行わない。
- 過去の会話、マイルストーン名、一般的なPython構成から現在状態を断定しない。
- 次作業候補は根拠がある最小限に留める。

## Output

ブランチ、作業ツリー、最新履歴、プロジェクト入口、正本、現在状態、矛盾、次の安全な作業候補を報告する。
