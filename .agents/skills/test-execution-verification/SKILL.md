# Test execution and verification

適用される`AGENTS.md`の権限・初動・検証規則に従い、ユーザーが限定した対象や禁止操作を越えない。
以下はこのSkillを使う作業の手順であり、タスク全体に別の承認工程を追加しない。対象・前提が変わっていない取得済みの証拠は再利用する。

## Workflow

1. 適用される`AGENTS.md`と依頼範囲を確認し、README、`pyproject.toml`、CI、既存テスト構成から正規コマンドと環境の特定に必要な箇所を読む。
2. 変更または要求に最も近いテストを選び、必須検証と回帰リスクを基に実行範囲と終了条件を定める。関連スイートや全体への拡大は、必須検証・失敗・影響範囲から必要な場合に限る。ユーザーの対象限定を越えない。
3. コマンドを一つずつ実行し、終了コード、失敗、警告、skip、収集件数、実行時間を記録する。
4. 表示上のpassとプロセス終了コードが矛盾する場合は、両方を報告して原因を切り分ける。
5. 失敗を実装修正、環境、fixture、順序依存、flaky、既知問題に分類する。証拠なしに既存失敗と断定しない。
6. 必要な検証が成功し、新たな変更・失敗・未解決リスクがなければ終了する。成功済みテストを理由なく再実行しない。
7. 要求に関連し、今回自動検証できないGUI、実バイナリ、複数OS等の範囲は、具体的な手動確認手順と未検証範囲を示す。例示だけを理由に検証対象を追加しない。

## Boundaries

- 検証だけの依頼ではコードやテストを修正しない。テストを削除、skip、期待値緩和して成功扱いにしない。
- 依存導入や環境変更が必要なら、実行前に影響を示す。
- 実行していない検査を成功扱いにしない。

## Output

実行環境、各コマンド、終了結果、失敗分析、検証済み範囲、未検証範囲を報告する。
