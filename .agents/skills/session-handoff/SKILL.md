# Session handoff

適用される`AGENTS.md`の権限・初動・検証規則に従い、ユーザーが限定した対象や禁止操作を越えない。
以下はこのSkillを使う作業の手順であり、タスク全体に別の承認工程を追加しない。対象・前提が変わっていない取得済みの証拠は再利用する。

## Workflow

1. セッション終了時のブランチ、作業ツリー、最近のコミット、remote同期の確認有無を取得する。
2. このセッションで実際に行った変更、実行したテスト、ユーザー確認を会話とリポジトリから再確認する。
3. `implemented`、`verified`、`unverified`、`incomplete`、`planned`、`deferred`、`out of scope`、`unknown`を分ける。
4. 決定済みの次セッションの目的と開始フェーズを一つに整理し、実装権限の有無を明記する。未決定ならその旨と決定に必要な事項を引き継ぎ、次作業を独自に確定したり、この理由だけで作成を止めたりしない。
5. 決定済みの次作業、または未決定事項の確認に必要な最小のファイルと、許可範囲内の確認コマンドを示す。
6. 保護すべき未コミット変更、禁止操作、既知の失敗、環境上の注意を記載する。
7. そのまま貼り付け可能で、古い状態を事実として固定しないプロンプトを作成する。

ユーザー指定の形式がなく、標準の出力枠が必要な場合は[handoff-template.md](references/handoff-template.md)を読む。

## Boundaries

- 引き継ぎ作成中に実装、closeout、Git統合、追加テストを行わない。
- remote同期やテスト成功を未確認のまま断定しない。
- 一般的な環境説明や禁止事項を過剰に繰り返さず、次セッションに必要な差分情報を優先する。

## Output

現在状態の短い要約と、貼り付け可能な次セッション用プロンプトを返す。
