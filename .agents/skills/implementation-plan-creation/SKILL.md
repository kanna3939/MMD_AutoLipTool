# Implementation plan creation

適用される`AGENTS.md`の権限・初動・検証規則に従い、ユーザーが限定した対象や禁止操作を越えない。
以下はこのSkillを使う作業の手順であり、タスク全体に別の承認工程を追加しない。対象・前提が変わっていない取得済みの証拠は再利用する。

## Workflow

1. 要求と適用される`AGENTS.md`を確認し、リポジトリ状態、README、パッケージ設定、コード、テスト、現行設計文書から計画に必要な範囲を読む。
2. 要求を現在の実装へ対応付け、変更理由、既存責務、入口、データ、状態、例外、外部境界を特定する。
3. In ScopeとOut of Scopeを検証可能な表現で固定する。
4. 対象ファイルを主変更、関連確認、テスト、文書に分類する。実在未確認のパスは候補と明記する。
5. 実装順序、データ契約、状態遷移、互換性、失敗時挙動を、実装者が判断を再発明しなくてよい粒度で記述する。
6. 最小テスト、リスクに応じた回帰への拡大条件、検証の終了条件、手動確認・ビルド確認の境界を定める。必須検証は維持する。
7. 完了判定できる受け入れ条件、リスク、禁止事項、報告形式を定義する。
8. 計画をコードと再照合し、古い文書や過去計画に引きずられていないことを監査する。

標準構成が必要な場合は[plan-template.md](references/plan-template.md)を読む。

## Boundaries

- コードやテストを実装しない。計画の保存を依頼された場合は指定成果物を作成・更新し、それ以外は本文を提示する。
- 将来機能のためだけの抽象化や無関係な再設計を計画へ混ぜない。
- 不明点が結果を大きく変える場合だけ質問し、それ以外は根拠付きの最小仮定で進める。

## Output

計画本文またはユーザーが指定した計画ファイルと、参照した根拠、未確定点を報告する。
