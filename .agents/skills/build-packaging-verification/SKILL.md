# Build and packaging verification

適用される`AGENTS.md`の権限・初動・検証規則に従い、ユーザーが限定した対象や禁止操作を越えない。
以下はこのSkillを使う作業の手順であり、タスク全体に別の承認工程を追加しない。対象・前提が変わっていない取得済みの証拠は再利用する。

## Workflow

1. 対象成果物と許可された操作を確認し、既存成果物の検査、ビルドによる生成、起動・インストール等の実行確認を区別する。対象の指定だけで他の操作を許可されたとみなさない。
2. 適用される`AGENTS.md`と、README、`pyproject.toml`、ロックファイル、ビルド・CI設定の関連箇所から、依頼された検査基準または正規のビルド方法・対象プラットフォームを特定する。
3. 既存成果物の検査だけなら再ビルドせず、その成果物を検査する。展開が必要な場合は元の成果物を保護し、書き込み禁止等の指定に従う。
4. ビルドが依頼範囲に含まれる場合は、既存変更と生成・削除パスを確認してから、許可された対象をリポジトリ記載のコマンドでビルドする。ビルド方式や依存管理ツールを推測で置き換えない。
5. 対象成果物の名前、サイズ、更新時刻、必要な内容を確認する。ビルドを実行した場合は終了コード、警告、生成先も確認する。必須ファイル、不要な開発ファイル、秘密情報、ライセンス文書、外部バイナリを検査する。
6. 実行確認が依頼範囲に含まれ、実行可能な場合は、最小のimport、CLI、起動、インストール、またはスモーク確認を選ぶ。インストール等の環境変更は実行可能性だけで許可されたと判断せず、`AGENTS.md`の権限規則に従う。手動確認と自動確認を分ける。
7. 再現性、クリーンビルドとの差、プラットフォーム制約、署名・Defender・外部ランタイムなど、関連する未確認点を記録する。未確認点の列挙を追加ビルドや環境変更の義務としない。

## Boundaries

- 公開、アップロード、署名、タグ作成は、ユーザーが明示的に依頼した場合だけ行う。
- ビルド成功と実行成功を同一視しない。
- 既存成果物の存在だけで今回のビルド成功を断定しない。
- 新規依存や外部バイナリが必要なら、導入前に理由、ライセンス、配布影響を示す。

## Output

ビルドコマンド、終了結果、生成物、内容検査、スモーク結果、配布上の問題、未確認事項を報告する。
