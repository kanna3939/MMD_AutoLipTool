# Release preparation

適用される`AGENTS.md`の権限・初動・検証規則に従い、ユーザーが限定した対象や禁止操作を越えない。
以下はこのSkillを使う作業の手順であり、タスク全体に別の承認工程を追加しない。対象・前提が変わっていない取得済みの証拠は再利用する。

## Workflow

1. 対象リリース、比較基点、ブランチ、未コミット変更、公開先を確認する。
2. 版数の正本と、コード、パッケージ設定、UI、文書、成果物の版数を照合する。
3. 変更履歴と実際の差分を照合し、破壊的変更、移行手順、既知問題を確認する。
4. ロックファイル、直接・間接依存、外部バイナリ、ライセンス、NOTICE、配布除外物を確認する。
5. 必須テスト、静的検査、ビルド、スモーク、プラットフォーム確認の証拠を集め、対象リリースとの対応を確認する。証拠不足を自動的な再実行・再ビルドの許可とせず、現在の依頼範囲と検証規則に従う。
6. 成果物の内容、再現性、秘密情報、デバッグファイル、サンプル、設定初期値を確認する。
7. release ready、条件付き、blockedのいずれかを根拠付きで判定する。

## Boundaries

- リリース公開、タグ、push、アップロード、署名を暗黙に実行しない。
- 版数変更が必要でも、ユーザーが更新を依頼していなければ提案に留める。
- ビルド検証が主目的なら`build-packaging-verification`を使用する。

## Output

判定、確認済み証拠、blocking issue、未確認事項、公開前に必要な操作を報告する。
