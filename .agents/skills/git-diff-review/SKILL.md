# Git diff review

適用される`AGENTS.md`の権限・初動・検証規則に従い、ユーザーが限定した対象や禁止操作を越えない。
以下はこのSkillを使う作業の手順であり、タスク全体に別の承認工程を追加しない。対象・前提が変わっていない取得済みの証拠は再利用する。

## Workflow

1. 指定された差分の種類と比較範囲を確定し、その解釈に必要なブランチ、作業ツリー、untracked、比較基点を確認する。
2. 対象差分の変更ファイル一覧を取得し、ユーザー依頼と無関係な既存変更を報告上で区別する。
3. 未ステージ、ステージ済み、コミット間から指定・必要な差分だけを確認する。ステージ済みのみ等の指定を理由なく広げない。
4. 各変更について、意図、呼び出し元、状態契約、例外処理、テスト、文書、依存関係への影響のうち関連する箇所を確認する。
5. 削除、名前変更、生成物、設定、権限、改行、文字コード、秘密情報を見落とさない。
6. 指摘を重要度順にまとめ、ファイルと位置、成立条件、影響、根拠を示す。

## Boundaries

- レビュー対象は読み取り専用とし、修正、stage、commit、restoreを行わない。報告書の保存が明示依頼されている場合は、その成果物だけを作成・更新できる。
- 変更量そのものを問題視せず、要求との不整合と実害を評価する。
- 問題がなければ、確認範囲と残る検証限界を示して明確に承認可能と述べる。

## Output

findingsを先頭に置き、続けて確認範囲、テスト状況、残留リスクを簡潔に報告する。
