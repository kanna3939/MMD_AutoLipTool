# Repair implementation

適用される`AGENTS.md`の権限・初動・検証規則に従い、ユーザーが限定した対象や禁止操作を越えない。
以下はこのSkillを使う作業の手順であり、タスク全体に別の承認工程を追加しない。対象・前提が変わっていない取得済みの証拠は再利用する。

## Workflow

1. 修正対象、再現条件、期待動作、非対象、既存変更を確認する。
2. 失敗経路を入口から追跡し、症状ではなく最小の原因を特定する。
3. 修正前に、既存テストまたは最小再現で問題を確認する。再現不能なら理由と検証限界を報告する。現在のコード等から原因と修正の根拠を確認できる場合は範囲内で進め、根拠不足なら推測で修正せず不足する証拠を示す。
4. 公開契約と既存正常系を維持する最小修正を行う。
5. 失敗を捉える回帰テストを追加または更新する。既存テストがその失敗を捉える場合は再利用し、同じ検出だけのために重複追加しない。テストを弱めて通さない。
6. 差分を検証前に監査してから対象テストを実行し、必須検証と回帰リスクに応じて関連回帰を広げる。成功後は、新たな変更・失敗・未解決リスクがなければ追加・再実行しない。
7. 差分を監査し、指定問題以外の変更と新しい仮定がないことを確認する。

## Boundaries

- 指摘外のリファクタ、機能追加、依存追加を行わない。
- 同じ試行が繰り返し失敗したら、原因仮説を見直してから次の手段を選ぶ。
- 許可範囲と公開契約を維持する内部変更は、補修に必要な最小範囲で行う。修正不能、または許可範囲・公開契約を越える設計変更が必要なら、範囲を拡大せず理由と選択肢を報告する。

## Output

原因、変更、回帰テスト、検証結果、未解決事項を報告する。
