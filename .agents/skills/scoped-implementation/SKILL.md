# Scoped implementation

適用される`AGENTS.md`の権限・初動・検証規則に従い、ユーザーが限定した対象や禁止操作を越えない。
以下はこのSkillを使う作業の手順であり、タスク全体に別の承認工程を追加しない。対象・前提が変わっていない取得済みの証拠は再利用する。

## Workflow

1. ユーザー要求、適用される`AGENTS.md`、必要なGit状態、関連コード、テストを確認する。計画がある場合は照合し、ない場合は要求を基準とする。計画書の新規作成・承認を実装の前提にしない。
2. In Scope、Out of Scope、受け入れ条件を現在の実装へ対応付ける。
3. 既存責務と公開契約を維持する最小変更を設計する。
4. 既存の命名、型、例外、ログ、設定、依存管理、プラットフォーム慣行に従って実装する。
5. 変更に関連する正常系、境界、失敗系が既存テストで検証できるか確認し、不足する要求・回帰の検出に必要なテストを追加または更新する。
6. 差分を検証前に監査してから最小の関連テストを実行し、必須検証と回帰リスクに応じて範囲を広げる。各コマンドの終了結果を記録する。成功後は、新たな変更・失敗・未解決リスクがなければ追加・再実行しない。
7. 差分を要求と再照合し、スコープ逸脱、不要な整形、文書・依存・配布影響を監査する。

## Boundaries

- 無関係なリファクタ、UI変更、依存追加、文書closeoutを行わない。
- 不明点が安全性や公開契約を変えない場合は、明示した最小仮定で進める。
- 外部書き込み、破壊操作、公開、重大な範囲拡大は、`AGENTS.md`の許可条件に従う。対象・操作・範囲が変わらない既存の明示的な許可を再要求しない。

## Output

確認ファイル、変更ファイル、実装内容、テストコマンドと結果、逸脱、残課題を報告する。
