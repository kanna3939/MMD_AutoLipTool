# Post-implementation review

適用される`AGENTS.md`の権限・初動・検証規則に従い、ユーザーが限定した対象や禁止操作を越えない。
以下はこのSkillを使う作業の手順であり、タスク全体に別の承認工程を追加しない。対象・前提が変わっていない取得済みの証拠は再利用する。

## Workflow

1. ユーザー要求、受け入れ条件、対象に必要なGit状態と変更ファイルを確認する。承認済み計画がある場合は照合し、ない場合は明示された要求を基準とする。計画の新規作成・承認をレビューの前提にしない。
2. レビュー対象の実装を、関連する入口、主要分岐、状態更新、出力、例外まで追跡する。
3. 要求ごとに、実装箇所とテスト証拠を対応付ける。
4. スコープ逸脱、欠落、互換性破壊、依存関係変更、テスト弱体化、文書不整合、プラットフォーム・配布影響の関連性を判断し、関連箇所を詳細に確認する。
5. 実行済みテストのコマンド、終了コード、対象範囲を確認し、未実行の検証を区別する。
6. 反証と例外条件を確認してから、受け入れ可否を明確に判定する。

## Findings

各指摘に重要度、ファイルと位置、成立条件、影響、根拠、必要な対応を含める。プロジェクトに分類規則がなければ、重大・次作業前・軽微の3段階を使う。

## Boundaries

- レビュー対象は読み取り専用とし、自動修正しない。報告書の保存が明示依頼されている場合は、その成果物だけを作成・更新できる。
- テストの存在とテスト成功を混同しない。
- 問題がなければ曖昧にせず、確認範囲内で受け入れ可能と述べる。
